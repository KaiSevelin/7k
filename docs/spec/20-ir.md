# 7K — Core IR

Core is the hub. Sandbox, Spider and every provider consume the IR and never the surface syntax.
This document defines the IR shape, the CST relationship, the diagnostic model, the mutation API
and the sidecar files.

The IR is presented as TypeScript declarations for precision. It is not a commitment to an
implementation language; the same shape serializes to JSON for provider plugins written in anything.

## 1. Two trees

```
source text
    |
    v
  CST  ---- lossless: every token, comment, blank line, byte offset
    |
    v
   IR  ---- resolved, normalized, analysable
```

**The CST is lossless.** Comments, whitespace, declaration order and formatting are all retained and
positioned. This is the single decision that cannot be deferred: a graph edit must be able to
rewrite one line and leave the rest of the file byte-identical, or Spider eats people's comments and
they stop trusting it. Re-serializing a file from the IR is a formatter operation, invoked
explicitly, never a side effect of editing.

**The IR is derived and never authoritative.** Every edit goes CST-first; the IR is rebuilt from it.
There is no path that writes the IR and expects the text to follow.

## 2. Identity

```ts
type NodeKind =
  | "label"  | "value" | "enum"   | "record" | "envelope" | "message" | "upcast"
  | "pipe"   | "service" | "package"
  | "saga"   | "schedule";

interface NodeId {
  kind:    NodeKind;
  pkg:     string;          // "acme.sales"
  name:    string;          // "OrderPlaced"
  scope?:  string;          // reserved; always absent today
}
```

`scope` is the forward-compatibility hedge for service and pipe instancing. Today every node is a
singleton and `scope` is absent. If per-channel deployment ever becomes necessary it arrives as a
concern for an implementation, and every analysis widens rather than being rewritten to become
instance-aware.
The field costs nothing now; retrofitting it later would touch every pass.

Identity is `(kind, pkg, name)`. **Renaming is therefore a refactoring, not a text substitution** —
it must rewrite every reference and the layout sidecar atomically. It is the most common structural
edit in any modelling language and should be built early.

## 3. Nodes

Every node carries provenance and a CST anchor.

```ts
interface Node {
  id:     NodeId;
  span:   Span;             // anchor into the CST
  anns:   Annotation[];
  labels: string[];         // declared labels, before upward propagation
  doc?:   string;           // leading comment
}

interface Span { file: string; start: number; end: number; }

interface Annotation { name: string; args: AnnArg[]; span: Span; }
```

### 3.1 Types

```ts
type TypeRef =
  | { t: "kernel";   name: KernelName; precision?: number; scale?: number }
  | { t: "ref";      target: NodeId }               // value | record | enum
  | { t: "list";     item: TypeRef }
  | { t: "map";      key: TypeRef; value: TypeRef }
  | { t: "unresolved"; text: string; span: Span };  // see section 5
```

`unresolved` is a first-class member of the union, not an error state. Half-finished models are
normal.

### 3.2 Constraints

Constraints are normalized at parse time: `length 5` becomes `{ min: 5, max: 5 }`, and a value's
constraints are folded together with its base value's so that every consumer sees one flat set.

```ts
type Constraint =
  | { c: "length";      min?: number; max?: number }
  | { c: "range";       min?: Literal; max?: Literal }
  | { c: "size";        min?: number; max?: number }
  | { c: "multipleOf";  value: Literal }
  | { c: "unique" }
  | { c: "pattern";     regex: string; dialect?: "re2" | "pcre" | "ecma" }
  | { c: "normalize";   ops: NormalizeOp[] }
  | { c: "default";     value: Literal }
  | { c: "example";     value: Literal };
```

### 3.3 Contract nodes

```ts
interface ValueDef extends Node {
  base:        TypeRef;               // kernel scalar, or another value
  constraints: Constraint[];          // folded
  root:        KernelName;            // the kernel scalar reached transitively
}

interface Field {
  name:        string;
  type:        TypeRef;
  optional:    boolean;
  constraints: Constraint[];
  anns:        Annotation[];
  since?:      Version;
  role?:       Role;              // envelope fields only
  derive?:     Path;              // envelope fields only; absent = copied each hop
  span:        Span;
}

interface RecordDef extends Node { fields: Field[]; invariants: Predicate[]; includes: NodeId[] }
interface EnvelopeDef extends Node { fields: Field[] }
interface EnumDef extends Node { members: EnumMember[] }   // no version: vocabulary, not a contract

interface Message extends Node {
  version:    Version;                // the only versioned thing in the Contract layer
  intent?:    "command" | "event";    // absent = incomplete
  visibility: { kind: "public" } | { kind: "internal"; scope: NodeId };
  envelopes:  NodeId[];               // resolved: the package's `envelopes` plus any `include`
  fields:     Field[];               // after include-splicing
  invariants: Predicate[];
}
```

Note `RecordDef.fields` is post-splice: `include` is resolved in the IR so no consumer has to implement
it, while `includes` is retained so Spider and the formatter can show the source form.

### 3.4 Topology nodes

```ts
interface Pipe extends Node {
  kind:        "queue" | "topic" | "stream";
  delivery:    "at-most-once" | "at-least-once" | "effectively-once";
  durable:     boolean;
  ordering:    { by: Path } | { by: null };
  retention?:  duration;
  maxSize?:    number;
  dedupWithin?: duration;        // set only by `delivery effectively-once within <d>`
  dlq?:        NodeId;                // implicit `<pipe>.dead` unless `dlq none`
  carries?:    MessageRef[];          // absent = inferred
}

interface Service extends Node {
  pkgNode:  NodeId;                   // the package of its file
  external: boolean;
  emits:    Emit[];
  reacts:   React[];
}

interface Emit  { message: MessageRef; pipe: NodeId; span: Span }

interface React {
  message:       MessageRef;
  pipe:          NodeId;
  subscription:  string;              // defaults to the service name
  accepts:       VersionRange;
  oncePer?:      Path;           // defaults to the message's @role(businessKey) field
  where?:        Predicate;           // subscription filter, not authorization
  requires?:     Predicate;
  replies:       { alts: MessageRef[]; allowNone: boolean };  // empty alts = sink
  concurrency:   { n: number } | { by: Path };
  retry:         RetryPolicy;
  dlq:           NodeId;              // resolved from the pipe default
  span:          Span;
}

interface RetryPolicy {
  retries:  number;                   // default 3; attempts are always retries + 1
  delay:    duration;                 // default 1s, in milliseconds
  backoff:  "linear" | "exponential"; // default exponential
  max?:     duration;                 // caps each wait, not their total
}

interface Package extends Node {
  parent?:   NodeId;                  // derived from the dotted name
  children:  NodeId[];
  owns:      NodeId[];                // every declaration in the file
  declared:  boolean;                 // false for an implied intermediate package
  envelopes: NodeId[];                // the envelope records every message here carries
  layers:    Layer[];                 // rank order, lowest first
}

interface Layer { name: string; members: NodeId[]; span: Span }

```

> **Lower to values, never to source text.** Every field above that a runtime acts on is a value: a retry
> policy is four numbers rather than the clause's text, and a `version` is `1.0` rather than the literal
> `v1.0` that canonical JSON would have to strip. A consumer that has to parse an IR field is a second
> parser for something Core already parsed, and the two will diverge — which is the whole reason the IR
> exists. If a consumer has to parse it, the IR lowered it too late (D73).

### 3.5 Process nodes

```ts
interface Saga extends Node {
  version:  Version;
  start:    { message: MessageRef; keyedBy: Path; assigns: Assign[] };
                                     // keyedBy resolved: explicit, else the start
                                     // message's @role(businessKey) field
  state:    Field[];
  steps:    Step[];
  deadline?: { after: Duration; terminal: "abandon" };
  terminals: { on: "complete" | "reject" | "abandon"; send: MessageRef }[];
}

interface Step {
  name:         string;
  send:         MessageRef;
  outcomes:     Outcome[];          // one per `on`
  timeout?:     { after: Duration; action: Action };
  undo:         { with: MessageRef } | { none: true } | undefined;
  span:         Span;
}

interface Outcome { on: MessageRef; keyedBy?: Path; action: Action; span: Span }
                                     // keyedBy overrides correlation on this await
type Action =
  | { a: "continue"; assigns: Assign[] }
  | { a: "reject"; reason: string }
  | { a: "abandon" };

interface Schedule extends Node {
  cron:      string;
  timezone:  string;               // required
  send:      MessageRef;
  onMissed:  "skip" | "once" | "all";   // required
}
```

Scenarios are **not** IR nodes: a scenario file references a package rather than declaring in it, so it
parses to its own tree alongside the model. Core checks it against the model (a mock reply within the
service's `replies`, a payload against its message contract) and hands it to a runtime.

### 3.6 Derived facts

Computed by Core, never written by hand, exposed to every consumer so no two tools derive them
differently:

```ts
interface Derived {
  pipeMessages:    map<NodeId, MessageRef[]>;  // declared or inferred
  pipeLabels:      map<NodeId, string[]>;      // upward label propagation
  messageLabels:   map<NodeId, string[]>;
  packageEdges:    PackageEdge[];              // aggregated service edges
  boundaryPorts:   map<NodeId, MessageRef[]>;  // crossing edges per package
  boundaryPipes:   NodeId[];                   // pipes with an @external producer or consumer
  producersOf:     map<MessageRef, NodeId[]>;
  consumersOf:     map<MessageRef, NodeId[]>;
  facetImpact:     map<NodeId, NodeId[]>;      // what a value change reaches
  deployOrder:     DeployConstraint[];
}
```

## 4. Analyses

Each produces diagnostics (section 5). Topology analyses run without the Process layer present.

| Code | Severity | Meaning |
|---|---|---|
| `orphan-message` | warning | emitted but never consumed, or consumed but never emitted |
| `unrouted-message` | error | emitted to, or awaited from, a pipe whose declared `carries` excludes it |
| `envelope-break` | error | a hop cannot carry a `@propagate` field its inbound messages carry |
| `missing-dedupe-key` | error | `at-least-once` or `effectively-once` consumer with neither a `@role(businessKey)` field nor an `once per` override |
| `package-cycle` | error | dependency cycle between packages |
| `tier-violation` | error | a package depends on a higher layer |
| `internal-scope` | error | an `@internal` scope that is not an ancestor of the declaring package, so it opens the message to a package beside it rather than above |
| `internal-leak` | error | a service consumes another package's `@internal` message |
| `version-mismatch` | error | a producer may emit a version no consumer accepts |
| `deploy-order` | warning | a consumer pins an exact version, so it must deploy before any producer bumps |
| `value-narrowing` | error | a refinement loosens a `length`, `size`, `range` or `multipleOf` its base set. Dropping a bound is fine — the base still binds — only widening one is wrong |
| `version-classification` | error | declared bump does not match the computed change class |
| `unclaimed-role` | warning | a role no field in the package claims, over its messages and the envelopes it applies; the dependent feature is named |
| `dedup-window-short` | warning | deduplication window shorter than the producer retry horizon |
| `ordering-defeated` | warning | consumer parallelism that is unkeyed, or keyed differently from the pipe |
| `filter-blocks-await` | error | *(Process layer)* a saga awaits a message the subscription filters out |
| `filter-on-queue` | warning | every subscription to a message on a queue filters it, so a message all of them decline is consumed and gone. Exhaustiveness over arbitrary predicates is undecidable; one unfiltered subscription is the decidable test |
| `filter-scope` | error | a `where` predicate reads `message` or `claim` rather than `envelope`. A bare path is not flagged: it cannot be told from an enum member without types |
| `reply-without-emit` | error | a message in `replies` has no matching `emits` |
| `unexplained-emit` | warning | a `@command` emitted that no `replies`, saga or schedule accounts for. Events are not checked: what prompts a service to publish a fact about its own work is its internals (D83) |
| `command-on-topic` | warning | a `@command` fanned out to every subscriber |
| `event-on-queue` | warning | an `@event` on a point-to-point pipe |
| `case-collision` | error | two declarations differing only in case |
| `foreign-mutation` | error | an `upcast` for a message another package owns. The other two forms the prose names are not expressible: there is nowhere to annotate a foreign declaration, and a same-named local declaration is a new one in a different package |
| `unhandled-outcome` | warning | *(Process)* a saga step's `on` clauses do not cover the handler's outcome space |
| `timeout-under-deadline` | error | *(Process)* a step awaiting another saga's terminal messages times out before that saga's deadline, orphaning it |
| `saga-cycle` | error | *(Process)* sagas start each other's start messages in a cycle |
| `saga-liveness` | error | *(Process)* a path reaches no terminal: a step with no timeout *and* no deadline, or one with no `on` clause at all |
| `state-unset` | error | *(Process)* saga state read before anything assigns it, or a field read or assigned that `state` does not declare |
| `unbounded-step` | warning | *(Process)* a step with no timeout, bounded only by the saga's deadline |
| `uncompensated` | warning | *(Process)* a step with neither `undo with` nor `undo none` |
| `saga-key-missing` | error | *(Process)* an awaited message has no business key and no `keyed by` override |
| `saga-key-mismatch` | error | *(Process)* an awaited message's key type does not match the saga's |
| `schedule-overrun` | warning | *(Process, **runtime**)* an occurrence still running when the next is due. Not knowable statically; a runtime reports it, and the sandbox does |
| `claim-subject-internal` | warning | a subject-identity `requires` on a pipe with no external producer |
| `mock-outside-outcome-space` | error | *(Process)* a mock replies with a message outside the service's declared `replies` |
| `subscription-collision` | error | two **services** share a subscription name on one pipe, or one service reads one message twice through one name. Several `reacts` sharing a name is one subscription dispatching on type, which is ordinary |
| `external-bound` | error | an implementation is asked to generate an `@external` service |
| `contract-fragmentation` | info | a package's public messages have disjoint consumer sets |
| `liveness-over-lossy-pipe` | error | *(the Process layer)* progress depends on an `at-most-once` pipe |

## 5. Partial models are normal

A text file is always a complete document. A canvas produces half-finished things constantly: a
service with no pipes, an edge dragged into empty space, a saga with one step. Every analysis
must degrade rather than crash or spew false errors.

```ts
type Severity = "error" | "warning" | "info" | "incomplete";

interface Diagnostic {
  code:     string;
  severity: Severity;
  message:  string;
  span:     Span;
  related?: { span: Span; message: string }[];
  fixes?:   Mutation[];              // offered as quick-fixes
}
```

`incomplete` is distinct from `error`. *"This service emits nothing"* is incomplete; *"this
service emits a message no pipe carries"* is an error. Spider shows incompleteness as a visual
state; CI fails on errors only.

Three rules every analysis follows:

1. An `unresolved` type never produces a downstream error — the resolution failure is reported once,
   at its own span, and dependent checks return "unknown".
2. A missing required clause is `incomplete`, not `error`, unless something else depends on it.
3. No analysis throws. Every pass returns diagnostics.

## 6. Sidecars

Presentation is not the model. Three sidecar files, all keyed by `NodeId`, all optional, all safely
deletable — a missing sidecar degrades to auto-layout, derived forms and the whole model, never to a broken
one.

```
model/              *.7k   the truth
.7k/views.json      named lenses: which packages, services, pipes and labels to draw
.7k/layout.json     per view: node positions, edge waypoints, collapse state
.7k/forms.json      optional per-record composer hints: widget, label, field order
```

### 6.1 views.json

A **view** is a named lens over the model — a saved filter on the diagram. It is presentation, not
language: it feeds no analysis and changes only what is drawn, so by the rule in `00-overview.md` it is
configuration rather than a construct.

```json
{
  "WebFlow": {
    "include": ["package:acme.retail.sales", "package:acme.retail.ticketing"],
    "exclude": ["service:KioskBridge"]
  },
  "PiiFlow":   { "include": ["label:pii"] },
  "Perimeter": { "include": ["label:external"] }
}
```

Selector forms: `package:<name>`, `service:<name>`, `pipe:<name>`, `label:<name>`.

Resolution:

- **Set semantics.** Every `include` unions, then every `exclude` subtracts. Order is irrelevant, and an
  `exclude` cannot be undone by a later `include`.
- **Includes are rules, not lists.** `package:acme.retail.sales` picks up a service added to that package
  later. That is why `exclude` exists: without it, one unwanted member forces enumeration by hand, and the
  lens goes stale the next time someone adds a service.
- **A view closes over its edges.** Including a package brings in everything it owns; including a service
  brings in the pipes it emits to and reacts from; including a pipe brings in both ends. An edge leaving the
  view renders as a **boundary port**, the same aggregation used for a collapsed package.

Coordinates are not in the model: it would put diff noise on every drag and make the model file
describe the tool rather than the system. Form hints are excluded for the same reason — the composer
derives its widgets from kernel types and constraints, which is what makes it work for user-defined
facets it has never seen.

Rename must update the sidecars in the same operation that updates the source.

## 7. Mutation API

Spider edits through this. So does any CLI refactor command and any future LSP code action — one
implementation, three front ends. Every mutation is a **surgical CST edit**, never a
re-serialization.

```ts
interface Mutation { op: string; /* op-specific fields */ }

// structural
addService(pkg, name)                 removeService(id)
addPipe(pkg, name, kind, delivery)    removePipe(id)
connectEmit(service, message, pipe)   disconnectEmit(service, message, pipe)
connectReact(service, message, pipe, opts)
setPipeAttr(pipe, attr, value)
moveToPackage(decl, package)          extractPackage(name, members[])

// moveToPackage relocates a declaration into another package's file, since a
// package is one file. It is the largest structural mutation in the API, the
// only one that moves text between files, and the only one that can change a
// message's wire type - so it reports that consequence before applying.

// data
addValue(pkg, name, base, constraints[])
addRecord(pkg, name)                  addField(record, name, type, optional)
addMessage(pkg, name, version)        includeEnvelope(message, envelope)
setConstraint(target, constraint)     removeConstraint(target, constraintName)

// cross-cutting
rename(id, newName)                   // updates references + sidecars atomically
addLabel(target, label)
```

Each returns the resulting text edits plus diagnostics, so a caller can preview before applying.

### 7.1 Write-through

Spider has no unsaved buffer. Every mutation writes the file immediately, and a file watcher
reloads on external change. That one rule eliminates the entire class of conflicts between a graph
editor holding dirty state and an external editor changing the same file. Undo is a command stack of
inverse mutations, not a dirty buffer.

### 7.2 Round-trip property tests

The mutation API is the most trust-sensitive part of the system, and it wants property-based tests
from the first commit:

1. `apply(op) -> text -> parse -> IR` matches the expected IR.
2. **Every byte outside the mutated span is unchanged.** Comments, ordering and formatting survive.
3. `apply(op)` then `apply(inverse(op))` yields byte-identical text.
4. `format(format(x)) == format(x)`.

Property 2 is the one that decides whether people keep using the graph editor.

## 8. What an implementation looks like

An implementation consumes the IR. **7K does not specify implementations** - this is the shape Core
assumes of one, not a conformance requirement. The sandbox is one such implementation, and its existence
is what keeps the three layers free of technology names.

```ts
interface Provider {
  name: string;
  validate(model: Model): Diagnostic[];   // can I satisfy this model? in my own terms
  emitCode(model: Model): FileSet;
  emitInfra(model: Model): FileSet;  // Terraform / Pulumi / Bicep - 7K owns no state
}
```

`validate` is the whole interface that matters. **Core has no capability vocabulary**, so it checks nothing
about technology: it hands over the IR and collects diagnostics expressed in the implementation's own
terms.

That is stronger than Core knowing a fixed list of capabilities, because an implementation can refuse for
reasons the language has no words for. The division of labour: 7K states what the system must do; an
implementation says whether it can.

**An implementation may fail, never weaken.** It satisfies what the model declares or refuses to build -
never silently downgrading an `at-least-once` pipe, altering a message shape or reordering a saga. The
moment an implementation may weaken a declaration, the model becomes a lie.

A model declaring `ordering by tenantId` with a 30-day timeout, handed to an implementation whose queues
cap delay at 15 minutes, must fail at build time with a clear message. A capability mismatch discovered at
3am is exactly the failure 7K exists to prevent.

**Three published artifacts keep implementations interoperable**, and nothing else is mandated:

| Artifact | Why it is specified |
|---|---|
| the **IR** (this document) | every implementation reads the same model instead of re-parsing and drifting |
| **canonical JSON** (`01-kernel.md` section 7) | a message is interchangeable between implementations |
| the **trace format** | any runtime's output is readable by any tool |

A binding format is deliberately **not** among them. How an implementation is told which broker a pipe
becomes is its own business.
